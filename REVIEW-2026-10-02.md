# Code review and regression results — October 2, 2026

This review covers the PHP application/API, Swift iOS client, installation schema, and scheduled jobs. It includes targeted source review and executable regression checks. It is not a claim that every line or every user workflow has been independently verified, or that the application is defect-free. Changes remain local; no production deployment or production data changes were made.

## Corrections

- **Group access:** Implemented the requested policy: mixed-client groups require unrestricted caseload access. Both current memberships and historical attendance count. Web and API list/detail/write paths enforce the policy; entirely assigned groups remain available to scoped staff.
- **Offline iOS records:** Failed or rejected synchronization retains queued records and displays an error. Queue reads/writes propagate failures instead of silently replacing corrupt data or claiming a save succeeded. Account identity gates enqueue/replay, and responses from a previous login cannot overwrite a new session. Stable replay keys prevent duplicates.
- **API record IDs:** Six creation endpoints now return the created entity ID rather than an audit-log ID.
- **Notes and homework:** Note edits can attach or detach their training track. Note creation and generated homework share a transaction, preventing partial persistence when homework storage fails.
- **Scored assessments:** iOS uses configured scale labels/values, including negative scales. API submissions store the normalized percentage, and history/detail use that percentage.
- **API numeric values:** Monetary fields and unread counts use JSON types compatible with the actual Swift models.
- **Client merge:** Related records previously omitted from merges now follow the retained client. Overlapping cohort memberships and attendance preserve participation without duplicating it. Coverage is checked against client foreign keys in the installation schema.
- **Case export:** ZIPs now contain structured case records in addition to the PDF/HTML summary and document attachments. Reusable access tokens and replay keys are excluded. Missing document attachments are explicitly listed; archive failures no longer silently produce an incomplete success response.
- **Fresh installations:** Added the missing client_notes.track_id column, index, and foreign key to the base schema. Existing installations should verify whether the existing dist/migrations/mig_2.62.0.sql migration has already been applied; do not blindly reapply it.
- **Scheduled jobs:** Failed database dumps do not leave apparent successful backups. Backups use private permissions and atomic publication. Session reminders remain retryable when either recipient fails. Offsite ZIP generation handles unsuccessful archive opening. Email ingestion saves before moving and uses a stable replay key. Installer instructions schedule report processing daily so weekly/biweekly schedules can run.
- **iOS documents/homework:** Download previews use separate protected temporary files with cleanup. Document/homework loading and homework completion surface failures. Waitlist is available in the iOS client status choices.
- **Form messages:** Removed double escaping of translated form errors and portal notices while retaining escaping of embedded markup.

- Four existing Node test files; existing accessibility checks; four translated form-message checks.

- Swift offline queue harness: eight checks covering identity, replay, rejected responses, corrupt storage, write failures, and sign-out.
- Actual Swift response models decode 11 populated API response fixtures.
- Cron test doubles verify backup failures/permissions, all reminder delivery combinations, and email save-before-move/replay behavior. These do not contact an email provider.
- Xcode Debug build for the arm64 iOS simulator succeeded with code signing disabled.
- Rebuilt dist/cms_dist.tar.gz and compared every bundled web/cron source plus installer/schema against the working files. The archive is ignored by Git. The old unpacked dist/cms_dist directory was not refreshed; use the newly built archive.

Database tests used a dedicated temporary MariaDB instance with networking disabled, synthetic records, and temporary configuration. Production configuration was not loaded by these harnesses.

## Remaining verification and limitations

- Live Microsoft Graph delivery, SSO/passkeys, external services, production hosting configuration, and physical-device behavior require environment-specific checks. A successful build or route smoke check does not verify every interactive workflow.
- Browser keyboard/screen-reader behavior and iOS Quick Look presentation/cleanup need hands-on validation; automated accessibility checks do not establish full WCAG conformance.
- Legacy offline records without a verifiable owner remain preserved rather than being submitted under an arbitrary account. Corrupt queue recovery is not automated.
- The scored-assessment correction applies to new submissions; historical percentages created by the old mobile endpoint have not been recalculated.
- Retrying a partially delivered reminder can resend to the recipient whose earlier delivery succeeded; there is no per-recipient delivery ledger.
- Email subject matching still depends on client names and can be ambiguous when names overlap or are duplicated.
- Structured case exports include more data than the human-readable PDF summary. Work-log signature files are not separately copied into the ZIP; their stored references remain in the structured records.
- Existing review documents contain additional historical findings and deployment considerations. This report does not certify all prior audit items as resolved.

The preexisting Xcode user-interface state change was preserved.
